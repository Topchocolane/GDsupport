# GDsupport

A small, local harness that lets an open-weight model build and fix Godot 4.6 projects on its own: it writes files,
runs the project headless, writes and runs its own behaviour tests, and only gets to say "done" after a clean run.
No training is involved. Everything here is the harness around a zero-shot model, plus the exams used to measure it.

Tested with Qwen3.6-35B-A3B (MLX, 8-bit) on a Mac Studio (M4 Max, 128 GB), Godot 4.6.3.

## What the harness does

- **Tools:** `list_files`, `read_file`, `write_file`, `run_project` (headless Godot, returns errors with the failing
  line quoted), `test_project` (the model's own GDScript test, run inside the project), `finish`.
- **Finish guard:** `finish` is refused until the project runs cleanly and, with the test tool on, a self-test passes.
- **Error hints** (`GD_HINTS`): short, grounded notes for the errors this model hits most (project.godot `[input]`
  syntax, text written into binary resources, unknown identifiers).
- **Targeted property sheets** (`GD_REF`, `GD_REF_AUTO`): when a task mentions UI layout presets or particles, its
  first message gets a short reference generated by the engine itself (`tools/ref/*.gd`): the 16 Control layout
  presets exactly as the editor writes them, particle enum values, and one sample scene saved by Godot.
- **Scene property lint** (`GD_LINT`, `tscn_lint.py`): Godot silently drops a property name it does not know when it
  loads a `.tscn`, so `trails_enabled = true` (the real name is `trail_enabled`) runs with no error and does nothing.
  The lint checks every property line against the engine's own property lists (`tools/ref/class_props.json`, dumped
  by `tools/ref/class_props.gd`) and puts the misses at the top of every run report.
- **Sandbox:** projects run under macOS `sandbox-exec` with writes limited to the project's temp dir.

All of the above is on by default. Each switch can be turned off with its environment variable set to `0`
(`GD_TEST_TOOL`, `GD_HINTS`, `GD_REF_AUTO`, `GD_LINT`; `GD_REF=` empties the sheet list).

## Setup

- macOS on Apple Silicon (MLX, and the run sandbox uses `sandbox-exec`).
- Godot 4.6.3. Set `GODOT=/path/to/Godot` if it is not at `~/apps/Godot.app/Contents/MacOS/Godot`.
- Python 3.11+ with `pip install -r requirements.txt`.
- An MLX model, e.g. `mlx-community` Qwen3.6-35B-A3B 8-bit. Peak memory for a 60-task batch is about 60 GB.

```
python tests/test_gd_run.py                                   # runner self-test: "6/6 as expected"
python gd_exam.py <model dir> - mytag 20                      # our 60-task exam -> eval/projects_mytag.json
python eval/regrade_corrected.py eval/projects_mytag.json     # adds the corrected column (see below)
GD_SEED=1 python gamedevbench/gdb_exam.py <model dir> mytag 20 0 --display   # GameDevBench, needs GDB_ROOT
```

Re-running the same command after an interruption resumes from `eval/ckpt/` (or `gamedevbench/ckpt/`).

## Results

All numbers are from this harness with Qwen3.6-35B-A3B-8bit, no fine-tuning. Raw per-task results (no transcripts)
are in `results/`. **Same seed is not deterministic** here: two runs of the same code and seed matched on only 30 of
60 trajectories, so read differences of about 3 tasks on the 60-task exam as noise.

### Our 60-task exam (`eval/gd_projects.json`, 30 2D + 30 3D)

"Behaves" = the finished project runs and passes the task's scripted behaviour checks. The corrected column re-grades
4 tasks whose original checks were wrong (`eval/regrade_corrected.py`; the legacy column is kept so older runs stay
comparable).

| Run | Seed 1 | Seed 2 | Corrected (s1 + s2) |
|---|---|---|---|
| v1 harness (test tool + hints) | 45 | 47 | 47 + 49 |
| **v2 = v1 + targeted sheets + lint** | 44 | 49 | 45 + 51 |
| v1 + sheet in every prompt | 31 | | |
| v1 + lint only | 45 | | |
| v1 + sheet in every prompt + lint | 28 | | |

The sheet hurts badly when it is put into every task's system prompt (45 to 31 on seed 1: tasks burn their turns and
stop finishing, 32 to 19 finished), and is neutral when attached only to tasks that mention its area.

### GameDevBench (external, 329 usable tasks)

[GameDevBench](https://arxiv.org/abs/2602.11103) (Apache-2.0, not included here). Under Godot 4.6.3 the ground truth
passes on 329 of 333 tasks and every starting project fails, so those 329 are used. One seed per row.

| Run | Pass | No verdict (timeout / no marker) |
|---|---|---|
| v1 harness, 20 turns | 33 (10.0%) | 9 |
| v1 harness, 40 turns | 34 (10.3%) | 4 |
| bare model (no test tool, no hints) | 27 (8.2%) | 7 |
| **v2 harness, 20 turns** | **41 (12.5%)** | 10 |

- v2 vs v1, paired: 19 tasks gained, 11 lost (sign test p about 0.2, **not significant on one seed**). The gain is
  concentrated in UI tasks (6 to 18). Of the 10 lost non-UI tasks, 8 never received a sheet or a lint message, so
  they ran the same harness as v1 and the loss there looks like run-to-run noise.
- On the 109 UI and particle tasks that did not always pass: v1 2, sheet in every prompt 12, plus lint 13, v2 13
  (paired v2 vs v1: +12 / -1).
- "No verdict" means the benchmark's test scene printed neither PASSED nor FAILED, mostly the 90 s timeout. They are
  scored as failures, like the official grader, but listed separately.
- Self-test precision does not transfer: on our exam, 85 of 99 projects whose self-test passed were really correct;
  on GameDevBench only 23 of 141 were. GameDevBench's hidden checks often look for names and values the task text
  does not state.

**Caveats against the official leaderboard:** the official setup uses Godot 4.4.1 (we use 4.6.3), a different agent
scaffold, and for many models image input; this harness is text-only. Our model is also a newer generation than the
open models on the board. Treat the comparison as a rough placement, not a ranking.

## What did not help

- **Fine-tuning** (LoRA SFT and rejection-sampling rounds on our own data): below the zero-shot model with this harness.
- **More turns:** 40 instead of 20 turns gave 34 vs 33 on GameDevBench, at nearly twice the time. The extra turns
  went into more self-tests passing (141 to 187), not more real passes.
- **Per-flag hint A/B tests:** seven hint changes each looked like gains on one or two seeds; combining the best
  three gave 40 vs 45 on a fresh seed (winner's curse). None are on by default (`GD_H2` keeps them for experiments).
- **"Red first"** (re-running a passing self-test on a logic-stripped stub, `GD_REDFIRST`): weak tests turned out not
  to predict wrong projects in offline replay, so it is off.
- **An API lookup tool** (`GD_DOCS_TOOL`, `gd_docs.py`, needs `godot --headless --doctool` output in `godot_docs/`):
  the model almost never called it.
- **Any reference text in every prompt:** see above.

## About the exam

- The 60 tasks and their checks (`eval/gd_projects.py` builds `eval/gd_projects.json`) were written with Claude.
  They are meant **for evaluation only**; do not use them as training data.
- Graders were audited with positive and negative controls (`eval/control_audit.py`): logic-stripped stub projects
  pass 0 of 56 checks, runs with the inputs removed pass 0 of 13. The audit also found the 4 wrong checks fixed in
  the corrected column (for example, `crate_push` measured after the crate had already slid off the floor).

## Layout

```
gd_agent.py         agent loop, tools, finish guard, hints, sheets, lint hook
gd_run.py           headless Godot runner (sandboxed), error parsing, probes, test harness
gd_exam.py          our 60-task exam
tscn_lint.py        unknown-property lint for .tscn/.tres
tools/ref/          engine-generated sheets and the class property dump (+ the .gd scripts that make them)
eval/               exam tasks, corrected grader, control audit
gamedevbench/       GameDevBench adapter and validator (set GDB_ROOT to a GameDevBench checkout)
results/            per-task results of the runs above, without transcripts
tests/              runner self-test
```

## Related work

- GameDevBench (arXiv 2602.11103), GameCraft-Bench and SWE-Game: agent benchmarks built on Godot projects.
- INTERVENOR and CoCoGen: code repair driven by compiler and execution feedback, the same loop applied here to a game
  engine.
- godot-correctness-mcp: static checks for GDScript projects (different scope; it does not run the project).
